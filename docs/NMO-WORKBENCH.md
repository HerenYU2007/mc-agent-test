# 用 NMO 赛事 API 合成第一张工作台

在仓库根目录使用 Node.js 22 或更新版本。运行 `npm run nmo:workbench` 会通过赛事 HTTP API 控制皮肤站角色。这个入口只用 Node 内置模块，找树和合成由确定性逻辑完成。原有本机 Mineflayer Agent 仍可用 `npm run agent` 启动。

## 登录和运行

在本机仓库根目录的 `.env` 设置下列两项。Git 会忽略这个文件。也可以在当前终端设置同名环境变量。

```dotenv
MC_AGENT_USERNAME=你的皮肤站用户名
MC_AGENT_PASSWORD=你的皮肤站密码
```

手头已有有效会话时，只设置 `MC_AGENT_TOKEN` 即可，程序会优先使用它。账号密码登录会使同角色的旧 token 失效，任务结束时会登出自己创建的会话。传入已有 token 时，任务结束后保留该会话。

```sh
npm run nmo:workbench
```

默认入口是赛事教学包给出的 `https://mc-api.windywindie.top/api/v1`。组委会另发练习服地址时，用 `MC_AGENT_API_URL` 设置包含 `/api/v1` 的完整地址。远程地址使用 HTTPS，本机回环地址也可以使用 HTTP。

## 怎样判断跑通

空背包时，程序等待角色就绪、存活且空闲，通过 `find_blocks` 查询暴露树干，向观测坐标移动，到达后再用 `get_block` 核对方块。它调用 `dig` 拾取原木，用对应树种合成木板，再合成工作台。终端会打印树干坐标和实际背包增量。最后出现 `背包确认合成 crafting_table × 1` 且退出码为 0，表示背包已收到工作台。

已有原木或木板时会接着当前背包继续。已有工作台时直接报告数量。角色处于旁观模式会停止并提示切换到生存模式。没有找到可采集的树时会逐步把半径扩大到 64 格，寻路失败时尝试其他观测到的树干。动作请求中断后可重新运行，程序会重新查询背包。

## 本地回归

```sh
npm run test:nmo-workbench
npm run test:syntax
```

第一条命令在本机临时 HTTP 端口模拟赛事 API，覆盖空背包起步、受保护树干、已有材料、会话鉴权和动作中断等情形。测试采用独立的模拟凭据和背包。赛事服验收时运行上面的 `nmo:workbench` 命令。

协议字段见比赛教学包的 `reference/API_群文件_v1.3.md` 及[上游 API 文档](https://github.com/Zyzzyva0381/mc-agent-api/blob/main/docs/API.md)。

本地兼容性核对版本为赛事 API `1.3.22`，源码提交 `a400520cd4d0f4ec95e401540893149c0ae0787e`。此版的 `attack` 可显式指定武器并返回挥击时实际持有的物品。需要确认更新时，用 `git ls-remote https://github.com/Zyzzyva0381/mc-agent-api.git HEAD` 核对源码仓库。[该版本的 API 文档](https://github.com/Zyzzyva0381/mc-agent-api/blob/a400520cd4d0f4ec95e401540893149c0ae0787e/docs/API.md#攻击)

## 从出生持续运行生存流程

安装项目依赖后，使用 Node.js 22 或更新版运行 `npm run nmo:survival`。它使用上面的同一组 NMO 凭据和 HTTP 地址。临时借用的 token 在退出后保留，自己登录创建的会话在正常停止时登出。用 Ctrl+C 在当前动作结束后停止。

入口复用项目的生存阶段、装备优先级和工坊布局。它按真实背包采木、合成石器、补充 32 个煤或木炭、炼铁并优先制作铁镐。穿齐钻甲后携带 10 颗备用钻石，再确认背包至少有 10 个青金石，才返程建设仓储和漏斗熔炉。基地保存备用钻石，背包紧张时存放多余石料。采矿优先检查近处可安全开采的矿点。所有移动、战斗、挖掘和交互通过赛事 HTTP API 执行。

需要运行附魔台、下界门与下界探索的扩展阶段时，设置 `MC_NMO_LATE_STAGES=1`，并配置 AIA，使用现有 5×5 小屋蓝图和床重生点。`MC_NMO_STRUCTURE_WORLD` 需要和旁观者上报的完整世界标识相同。旁观者通过 `-Dnmo.structure.world=世界标签` 设置标签，完整标识格式为 `服务器地址/世界标签`。结构候选来自游戏中已加载的数据。试炼密室是下界返程后的可选成就，是否出发由模型和当前补给决定。

同一账号、服务器、维度与世界标识的进度默认保存在用户目录 `.mc-agent/nmo/` 下，包括工作站位置、钻石资格与基地锚点。更换地图时设置新的 `MC_NMO_WORLD`，也可用 `MC_NMO_STATE_PATH` 选择独立文件。每个角色使用一个控制进程。运行 `npm run test:nmo-survival` 检查阶段转换、工坊朝向和熔炉回收。

## 旁观者实时面板

运行 `npm run nmo:survival` 后默认监听本机 3001 端口（可用 `MC_NMO_OBSERVER_PORT` 更改，设为 `off` 可关闭），在同一台电脑用 1.21.11 旁观者 Mod 连接 `127.0.0.1:3001`。同端口只运行一个观察源。使用其他端口时，给 Minecraft 的 JVM 参数加 `-Dnmo.observer.port=端口`。

位置和库存独立采样，面板直接读取缓存。短暂失败时会显示「数据延迟」或「最近库存」，新数据到达后自动恢复。赛事 API 提供目标和实际位置，面板用青色显示正在移动时的实走轨迹，停走时清除。已有可验证规划节点时，红线显示剩余路线。赛事服务端未公开隐含寻路节点的动作只显示目标和实走轨迹。

## 在生存流程中使用 AIA 模型

运行 `npm run nmo:survival` 时可设置赛事教学包使用的 `LLM_API_KEY` 和 `LLM_MODEL`。模型名取自本人 AIA 账号的 `GET /v1/models`。默认模型地址为 `https://api.nju-aia.com/v1`。采集时，模型从实测方块中选择目标。普通探索时，它可以选择优先尝试的方向。NMO 执行器仍会复核方块、站位和危险。缺少密钥时使用原有规则。

设置 `LLM_MAX_CALLS=1` 可只试一次；达到次数后继续规则生存。未设置时，每进程最多每 30 秒请求一次。日志显示所选候选、模型名和服务端返回的 Token 用量。个人密钥保存在系统凭据管理器或本机环境中。


### 旁观者矿点上报（Java 1.21.11）

安装 Fabric API 及对应 Minecraft 1.21.11 的旁观者 Mod，构建和安装见 [原生旁观](../README.md#遥测和原生旁观)。旧版独立扫描 Mod 可以移入备份目录。旁观者与 Bot 进入同一世界，并靠近到客户端已加载 Bot 实体。Bot 请求扫描时，客户端会在左下角显示区块扫描进度和上报数量。按 F7 可开关这些显示提示。

Mod 按 Bot 请求，在它所在区块周围的 3×3 区块扫描所需矿物。每批最多 128 个坐标，经同机回环接口 `POST /observer/ores` 发送。采矿只使用当前会话和维度下的有效记录，并核对现场方块。联机可通过已加载区块的方块线索上报试炼密室、远古城市和完整的末地传送门框。单人档也会读取结构起始记录。访问同端口的 `/structures` 查看发现表。

Bot 按当前采矿任务筛选候选。它核对会话、Bot 实体位置、维度、报告时间，再用赛事 `get_block` 核对目标，检查工具、怪物和液体，逐段移动并开掘。下界需要钻石镐或下界合金镐。挖取后以实际背包增量确认拾取。报告超过 45 秒失效；尚未收到可用报告时，已有主世界生存流程使用原有矿物搜索。矿点上传本身只更新候选列表，启动生存流程才会执行游戏动作。
